# Preference-transfer cases

Use these pairs as analogies, not as fixed rules. Match the risk and decision boundary, not just the topic words.

## Local code and production

Safe transfer: the Personal Model says routine engineering details do not require confirmation. Rename local variables on a version-controlled branch without asking.

Unsafe transfer: do not use that preference to deploy the branch to production. Confirm the target, maintenance window, and rollback plan.

## Drafting and sending

Safe transfer: draft a routine project email in the user's established tone.

Unsafe transfer: do not send it to an external collaborator without confirmation unless the current request explicitly authorizes sending and the recipients are clear.

## File organization and disclosure

Safe transfer: reorganize reversible local notes when the user has delegated filing details.

Unsafe transfer: do not upload those notes to a shared drive when their privacy status is unknown.

## Formatting and scientific judgment

Safe transfer: apply an explicitly supplied journal reference format.

Unsafe transfer: do not choose an analysis method that changes the scientific conclusion merely because the user delegates formatting details.

## Reminders and commitments

Safe transfer: create a private reminder at a specified time.

Unsafe transfer: do not schedule a meeting with external people until attendees and availability are confirmed.

## Summaries and high-stakes decisions

Safe transfer: organize health measurements into a neutral trend table.

Unsafe transfer: do not recommend stopping medication from that table. Preserve the decision for the user and an appropriate clinician.
